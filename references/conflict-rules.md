# 跨阶段冲突裁决表

四套上游 skill 各自自洽，串起来就会打架。本文件是唯一裁决处，冲突时按这里执行，**不要回去按某一方的 SKILL.md 原文办**。

裁决原则：

1. **正文层听写作，组件层听排版。** 读者读到的连续文字属于正文层；章节标题、标签、引言卡、代码块、签名卡、目录属于组件层。
2. **事实层听素材。** 任何阶段都不许为了效果新增事实。
3. **身份层听配置。** 署名、简介、CTA、品牌资产只有 `config/` 一个来源。

## A. 写作风格 ↔ 排版结构

| # | 冲突点 | khazix-writer 要求 | gzh-design 要求 | 裁决 |
|---|--------|-------------------|----------------|------|
| A1 | 小标题 | 绝大多数文章不加小标题，靠口语转场衔接 | 靠 `##` 分章，做编号 / 目录 / 标题组件 | **正文不写 `##`**，改埋 `<!-- sec: 中文名 \| tag: EN -->` 注释锚点。排版阶段把锚点当 `##` 用，渲染成主题的章节标题组件。读者看到的仍是顺流文章 |
| A2 | 冒号「：」 | 正文禁用，用逗号代替 | 正文标点一律全角（含全角冒号） | **正文层禁用**。组件层（章节标题、标签、代码块、图片说明、签名卡）不受禁令约束 |
| A3 | 破折号「——」 | 正文禁用 | 全角破折号属推荐标点 | 同 A2。正文不用，组件文案可用 |
| A4 | 双引号 | 禁用 `""` 和 `""`，用「」 | 要求把直引号 `"` 转成弯引号 `""` | **一律转成「」**，不是弯引号。校验脚本报的直引号仍要清零，修法是换「」 |
| A5 | 加粗 | 不大量加粗，超过 2 行的加粗算过度结构化 | 锚点层主色加粗，全文 ≤ 5 处 | 取交集：**全文加粗 ≤ 5 处，每处 ≤ 10 字**，不允许整句整段加粗 |
| A6 | 正文下划线标记 | 无此概念 | 每个正文段落主动标 1–3 个关键短语 | khazix 风格段落极短（常一句一段），逐段标会糊成一片。改为**按语义板块标 3–6 处**，全文密度约每 200 字 1–2 处，段落短于 30 字的一般不标 |
| A7 | bullet 列表 | 禁止用 bullet 罗列观点，超过 3 个要改散文 | 有列表 → 组件的映射规则 | **正文不产出 bullet**。素材里的清单在写作阶段就转成散文或文中数字编号（1、2、3），排版阶段不许再补 bullet 组件 |
| A8 | 尾部签名 | 有固定尾部（署名 + 投稿邮箱） | 用 `{{作者名}}` 占位签名区 | 都从 `config/author-profile.md` 取。**成品里签名区有且仅有一处**，写作阶段写了尾部 CTA，排版阶段就并入这一处，不另起一个 |
| A9 | 文章长度 | 4000–8000 字 | 无要求 | 依 khazix |
| A10 | 段落长度 | 段落要短，一句话成段是常态 | 无要求 | 依 khazix。排版组件不要试图把短段合并成大块 |

**A2/A3/A4 的例外统一说明**：代码块、行内代码、URL、英文专名、代码标识符内部一律保持原样，不做任何标点转换。

## B. 标题 ↔ 正文 / 封面

| # | 冲突点 | 裁决 |
|---|--------|------|
| B1 | viral-title 追求点击率，可能起出正文兑现不了的承诺 | 选定前对着 `article.md` 逐条核事实。数字、产品名、结论、对比对象必须在正文里真实存在 |
| B2 | 写作阶段也会自然产生一个标题 | 那只是工作标题。**最终标题以阶段 3 选定结果为准**，选定后同步回 `article.md` 顶部的 `# 标题` |
| B3 | viral-title 的标题可能含冒号 / 破折号 / 双引号 | 标题属组件层，**不受 A2–A4 禁令约束**。但同一篇里标题和正文的语气要一致，标题党到正文接不住就换一个 |
| B4 | 封面文字与标题不一致 | 封面上的标题和摘要**逐字复制**阶段 3 的结果，标点、空格、英文大小写都不许改。要换短版必须用户明确同意 |

## C. 封面品牌层

| # | 冲突点 | cover-skill 原文要求 | 裁决 |
|---|--------|--------------------|------|
| C1 | 真人头像 + 袋鼠 IP | 是强制项，缺了要停下来问 | **改为读 `config/brand-assets.md`**。配置里有就用配置里的形象，没有就跳过强制项走通用封面。原作者的头像和袋鼠资产不属于本 skill 用户，任何情况下都不使用 |
| C2 | 封面比例 | 不带平台参数时默认 16:9 | 公众号**锁 21:9（2100×900）**。用户显式指定比例时按用户的 |
| C3 | 四概念 → 选一 → 五比例 | 两段式 | 保留，不省。用户明说「随便出一个」时可只跑第一段并说明 |
| C4 | 中文文字与 Logo | 确定性合成，不让图像模型画 | 保留，这是硬规则 |
| C5 | 没有可用图像生成工具 | 未覆盖 | 走纯合成降级路线（HTML/SVG 排 21:9 文字封面），照跑四概念和 QA，并明确告知用户这是降级方案。**不要假装调用了图像模型** |

## D. 校验冲突

| # | 情况 | 裁决 |
|---|------|------|
| D1 | `validate_gzh_html.py` 报半角标点 WARNING，但那处是代码块 / URL / 英文专名 | 不改，在交付说明里注明豁免原因 |
| D2 | `validate_gzh_html.py` 想把 `"` 改成 `""`，A4 要求改「」 | 按 A4，改「」 |
| D3 | `check_article.py` 报禁用词，但那是引用他人原话 | 引用他人原话属事实层，不改词，改成用「」括起来并注明出处 |
| D4 | 两个脚本结论矛盾 | 以**产物形态**为准：`check_article.py` 管 `article.md`，`validate_gzh_html.py` 管 HTML。各管各的，不互相覆盖 |
